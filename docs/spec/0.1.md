# TLL Programming Language Specification 0.1

> Status: FROZEN (Draft for Bootstrap)
> Date: 2026-08-23
> Author: TLL Team

---

## 1. Design Philosophy

TLL is an **AI-Native** programming language. It is designed from first principles, not derived from any existing language's semantics.

### 1.1 Core Principles

1. **AI is a first-class citizen** — Agent, Intent, and Tool are native language constructs, not libraries.
2. **Immutable by default** — Every binding is immutable unless explicitly declared `mut`.
3. **Explicit over implicit** — No hidden coercions, no magic globals, no implicit `this`.
4. **Safety without garbage collection** — Ownership-based memory model (see §5), optional reference counting for shared types.
5. **One way to do things** — Minimal syntax surface, maximal consistency.
6. **Self-hosting target** — The language specification must be implementable in TLL itself. Bootstrap compilers are temporary.

### 1.2 Non-Goals

- TLL is not a superset or subset of JavaScript, TypeScript, Rust, Go, or Python.
- TLL does not aim for C-level raw pointer manipulation in 0.1.
- TLL does not support operator overloading in 0.1.

## 2. Lexical Structure

### 2.1 Source Encoding

TLL source files MUST be UTF-8 encoded. The file extension is `.tll`.

### 2.2 Comments

```tll
// Line comment: everything from // to end of line is ignored.

/// Documentation comment: attached to the following declaration.
/// Used by tooling to generate API docs.
```

Block comments are intentionally NOT supported in 0.1.

### 2.3 Keywords

The following are reserved keywords and cannot be used as identifiers:

```
let       mut       const     fn        return
if        else      while     for       in
break     continue  match     case      default
true      false     null      undefined
import    from      export    as        module
pub       priv      type      interface   impl
entity    api       application
async     await     defer
try       catch     throw     Result    Option
Some      None      Ok        Err
agent     intent    tool      spawn     send
self      Self      super     package
```

### 2.4 Identifiers

- Must start with a letter (`a-z`, `A-Z`) or underscore `_`.
- May contain letters, digits (`0-9`), and underscores.
- Case-sensitive.
- Convention: `snake_case` for variables and functions, `PascalCase` for types, `SCREAMING_SNAKE_CASE` for constants.

### 2.5 Literals

#### 2.5.1 Integers

```tll
42
0xFF        // hexadecimal
0o77        // octal
0b1010      // binary
1_000_000   // underscore separators
```

Integer type is arbitrary precision by default. Fixed-width types are `i8`, `i16`, `i32`, `i64`, `u8`, `u16`, `u32`, `u64`.

#### 2.5.2 Floats

```tll
3.14
1.0e-5
6.022e23
```

Float type is `f64` (IEEE 754 double precision) by default. `f32` is also available.

#### 2.5.3 Strings

```tll
"hello world"
"line one\nline two"
"unicode: 你好 🌍"

// Raw string: no escape processing
r"C:\Users\name"

// Multi-line string (triple quotes)
"""
This is a
multi-line string.
"""
```

Strings are immutable UTF-8 sequences. Mutable text uses `StringBuilder` from the standard library.

#### 2.5.4 Booleans

```tll
true
false
```

#### 2.5.5 Null

```tll
null
```

`null` is a value of type `Null`. It is NOT a member of any other type. Nullable types must be explicit: `Option<T>` or `T?` (sugar for `Option<T>`).

### 2.6 Operators and Punctuation

```
+    -    *    /    %    **    // arithmetic (+, -, *, /, %, power)
==   !=   <    >    <=   >=         // comparison
&&   ||   !                           // logical
=    +=   -=   *=   /=   %=          // assignment
->   =>   |>   @                      // special (arrow, fat-arrow, pipe, at)
.    ,    :    ;                      // punctuation
(    )    {    }    [    ]           // delimiters
?                                     // optional / error propagation
..    ..=                             // ranges (exclusive, inclusive)
```

## 3. Type System

TLL has a **static, nominative, structurally-augmented** type system with local type inference.

### 3.1 Primitive Types

| Type | Description | Default |
|------|-------------|---------|
| `bool` | Boolean | `false` |
| `int` | Arbitrary precision integer | `0` |
| `i8` `i16` `i32` `i64` | Signed fixed-width | `0` |
| `u8` `u16` `u32` `u64` | Unsigned fixed-width | `0` |
| `float` | 64-bit float | `0.0` |
| `f32` | 32-bit float | `0.0` |
| `str` | Immutable UTF-8 string | `""` |
| `char` | Unicode scalar value | `'\0'` |
| `Null` | The null type | `null` |
| `Never` | Bottom type (diverges) | — |

### 3.2 Compound Types

#### 3.2.1 Arrays

Fixed-size, homogeneous, value-type arrays.

```tll
let nums: [int; 5] = [1, 2, 3, 4, 5]
let bytes: [u8; 4] = [0xDE, 0xAD, 0xBE, 0xEF]
```

#### 3.2.2 Lists (Dynamic Arrays)

Heap-allocated, growable arrays.

```tll
let items: List[int] = [1, 2, 3]
items.push(4)
```

#### 3.2.3 Maps (Dictionaries)

```tll
let scores: Map[str, int] = {"alice": 95, "bob": 87}
```

#### 3.2.4 Tuples

Fixed-size, heterogeneous, value-type.

```tll
let point: (int, int) = (10, 20)
let person: (str, int, bool) = ("Alice", 30, true)
```

#### 3.2.5 Structs (Product Types)

```tll
pub struct Point {
    x: float,
    y: float,
}

pub struct User {
    id: int,
    name: str,
    email: Option[str],
    active: bool = true,  // default value
}
```

Structs are nominal. Fields are immutable by default; use `mut` on the binding to mutate.

#### 3.2.6 Enums (Sum Types)

```tll
pub enum Shape {
    Circle(float),           // radius
    Rectangle(float, float), // width, height
    Point { x: float, y: float },
}

pub enum Option[T] {
    Some(T),
    None,
}

pub enum Result[T, E] {
    Ok(T),
    Err(E),
}
```

Enums can carry data (tuple variants or struct variants). Pattern matching is exhaustive.

### 3.3 Function Types

```tll
type BinaryOp = fn(int, int) -> int
type Callback = fn(str) -> void
type AsyncFn = async fn(str) -> Result[int, Error]
```

Functions are first-class values. All functions are closures (they capture their environment by immutable reference by default, by value if `move` is specified).

### 3.4 Type Aliases

```tll
type UserId = int
type Handler = fn(Request) -> Response
type Matrix = [[float; 4]; 4]
```

### 3.5 Interfaces

Interfaces define behavior. Structs implement interfaces explicitly.

```tll
pub interface Drawable {
    fn draw(self, ctx: &Context) -> void
    fn bounds(self) -> Rectangle
}

impl Drawable for Circle {
    fn draw(self, ctx: &Context) -> void { ... }
    fn bounds(self) -> Rectangle { ... }
}
```

Interfaces support default methods:

```tll
pub interface Stringable {
    fn to_string(self) -> str
    fn print(self) -> void {
        io.println(self.to_string())
    }
}
```

### 3.6 Generics

```tll
pub struct Box[T] {
    value: T,
}

pub fn identity[T](value: T) -> T {
    return value
}

pub fn map[T, U](list: List[T], f: fn(T) -> U) -> List[U] {
    let result = List[U].new()
    for item in list {
        result.push(f(item))
    }
    return result
}
```

Generics are monomorphized at compile time (like Rust/C++), not type-erased (like Java).

### 3.7 Type Inference

TLL infers types locally. Function parameter types and return types MUST be explicit (no inference across function boundaries).

```tll
let x = 42          // inferred as int
let name = "Alice"  // inferred as str
let nums = [1, 2, 3] // inferred as List[int]

fn add(a: int, b: int) -> int {  // explicit params and return
    return a + b
}
```

### 3.8 Null Safety

`null` is NOT a valid value for any non-nullable type. Nullability is expressed via `Option[T]` or the `T?` sugar.

```tll
let name: str = "Alice"       // cannot be null
let nickname: Option[str] = None  // explicitly optional
let email: str? = null         // sugar for Option[str]

// Safe access
let len = email?.len()         // Option[int], None if email is None

// Unwrap with default
let display = email.unwrap_or("no email")

// Pattern match
match email {
    Some(e) => io.println(e),
    None => io.println("no email"),
}
```

### 3.9 Type Casting

No implicit conversions. Explicit conversion via constructor functions or `as` keyword for primitive widening:

```tll
let i: int = 42
let f: float = i as float   // explicit widening
let s: str = i.to_string()  // method-based conversion
```

Narrowing conversions require `try` and return `Result`:

```tll
let big: int = 100000
let small: Result[i8, OverflowError] = i8.try_from(big)
```

## 4. Syntax and Semantics

### 4.1 Variables and Bindings

```tll
let x = 5              // immutable, type inferred
let y: int = 10        // immutable, type explicit
mut z = 0              // mutable, type inferred
mut counter: int = 0   // mutable, type explicit
const MAX = 100        // compile-time constant
```

Shadowing is allowed:

```tll
let x = 5
let x = x + 1  // new binding, old x is shadowed (not mutated)
```

### 4.2 Functions

```tll
fn add(a: int, b: int) -> int {
    return a + b
}

// Single-expression function (implicit return)
fn multiply(a: int, b: int) -> int = a * b

// Void function (no return type annotation needed, or -> void)
fn greet(name: str) {
    io.println("Hello, " + name)
}

// Functions as values
let op: fn(int, int) -> int = add
let result = op(3, 4)  // 7
```

### 4.3 Control Flow

#### 4.3.1 If / Else

```tll
if x > 0 {
    io.println("positive")
} else if x < 0 {
    io.println("negative")
} else {
    io.println("zero")
}

// If is an expression
let sign = if x > 0 { "positive" } else if x < 0 { "negative" } else { "zero" }
```

#### 4.3.2 While

```tll
mut i = 0
while i < 10 {
    io.println(i)
    i += 1
}
```

#### 4.3.3 For

```tll
// Range-based
for i in 0..10 {       // 0 to 9
    io.println(i)
}

for i in 0..=10 {      // 0 to 10 inclusive
    io.println(i)
}

// Iterator-based
for item in items {
    io.println(item)
}

// With index
for (i, item) in items.enumerate() {
    io.println("{i}: {item}")
}
```

#### 4.3.4 Match (Pattern Matching)

```tll
match shape {
    Shape.Circle(r) => io.println("circle with radius {r}"),
    Shape.Rectangle(w, h) => io.println("rect {w}x{h}"),
    Shape.Point { x, y } => io.println("point ({x}, {y})"),
}

// Exhaustive check: compiler errors if a case is missing.
// Use _ as wildcard:
match code {
    200 => "OK",
    404 => "Not Found",
    _ => "Other",
}

// Match is an expression
let message = match status {
    Ok(data) => "Success: {data}",
    Err(e) => "Error: {e}",
}
```

#### 4.3.5 Break / Continue

```tll
for i in 0..100 {
    if i == 50 {
        break
    }
    if i % 2 == 0 {
        continue
    }
    io.println(i)
}

// Labeled break
'outer: for i in 0..10 {
    for j in 0..10 {
        if i * j > 50 {
            break 'outer
        }
    }
}
```

### 4.4 Error Handling

TLL uses `Result[T, E]` for recoverable errors and `panic` for unrecoverable errors.

```tll
fn divide(a: int, b: int) -> Result[int, DivideError] {
    if b == 0 {
        return Err(DivideError.ByZero)
    }
    return Ok(a / b)
}

// Using match
match divide(10, 2) {
    Ok(result) => io.println("result: {result}"),
    Err(e) => io.println("error: {e}"),
}

// Using ? operator (error propagation)
fn calculate() -> Result[int, Error] {
    let a = parse_int("42")?
    let b = parse_int("10")?
    return Ok(a + b)
}

// Unwrap (panics on Err) — use sparingly
let value = divide(10, 2).unwrap()

// Unwrap with default
let value = divide(10, 0).unwrap_or(0)

// Panic (unrecoverable)
fn assert_positive(x: int) {
    if x <= 0 {
        panic("expected positive, got {x}")
    }
}
```

`try/catch` is NOT supported. Errors are values.

### 4.5 Defer

```tll
fn process_file(path: str) -> Result<void, IoError> {
    let file = File.open(path)?
    defer file.close()  // runs when function exits, in reverse order

    let content = file.read_all()?
    io.println(content)
    return Ok(void)
}
```

`defer` statements execute in LIFO order when the enclosing scope exits.

### 4.6 String Interpolation

```tll
let name = "Alice"
let age = 30
let message = "Name: {name}, Age: {age}, Next year: {age + 1}"
```

Expressions inside `{}` are evaluated and converted to strings.

### 4.7 Pipe Operator

```tll
// Instead of:
let result = parse(validate(transform(input)))

// Use pipe:
let result = input
    |> transform
    |> validate
    |> parse

// With arguments
let result = input |> transform(mode: "fast") |> validate(strict: true)
```

`|>` passes the left value as the first argument to the right function.

## 5. Memory Model

### 5.1 Ownership

TLL uses an ownership-based memory model inspired by linear types:

1. Each value has exactly one owner at a time.
2. When the owner goes out of scope, the value is dropped (destructor runs).
3. Assignment and function parameters **move** ownership by default.
4. Borrowing allows temporary access without transferring ownership.

### 5.2 Move Semantics

```tll
let a = String.from("hello")
let b = a  // a is MOVED to b; a is no longer usable
io.println(a)  // COMPILE ERROR: use of moved value
```

### 5.3 Borrowing

```tll
fn length(s: &str) -> int {  // immutable borrow
    return s.len()
}

fn append(s: &mut String, suffix: str) {  // mutable borrow
    s.push_str(suffix)
}

let text = String.from("hello")
let len = length(&text)  // immutable borrow
io.println(text)  // OK, immutable borrows don't consume

let mut text2 = String.from("hello")
append(&mut text2, " world")  // mutable borrow
io.println(text2)  // OK
```

Borrowing rules:
- Multiple immutable borrows (`&T`) are allowed simultaneously.
- Only one mutable borrow (`&mut T`) is allowed at a time.
- Mutable and immutable borrows cannot coexist.
- Borrows cannot outlive the owner.

### 5.4 Reference Counted Types

For shared ownership, use `Rc[T]` (single-threaded) or `Arc[T]` (thread-safe):

```tll
let shared = Rc.new(String.from("shared"))
let clone1 = shared.clone()  // increments ref count
let clone2 = shared.clone()
// All three point to the same data; freed when last Rc drops
```

### 5.5 No Garbage Collector

TLL 0.1 has no GC. Memory is managed via ownership + borrowing + optional reference counting.

## 6. Module System

### 6.1 File-Based Modules

Each `.tll` file is a module. The module name is the file name (without extension).

```
src/
  main.tll          // module main
  utils.tll         // module utils
  models/
    user.tll        // module models.user
    product.tll     // module models.product
```

### 6.2 Imports

```tll
import utils                    // import module, access as utils.function_name
import utils as u               // import with alias
from utils import format, parse // import specific items
from utils import *             // import all public items (discouraged)
from models.user import User    // import from submodule
```

### 6.3 Exports

Only items marked `pub` are accessible outside the module.

```tll
pub fn public_function() { ... }
fn private_function() { ... }

pub struct PublicStruct { ... }
struct PrivateStruct { ... }

pub const MAX_VALUE = 100
```

### 6.4 Package Declaration

A package is a collection of modules. The root file declares the package:

```tll
// main.tll or lib.tll
package myapp {
    version = "0.1.0"
    license = "MIT"
}
```

## 8. Async Model

### 8.1 Async Functions

```tll
async fn fetch_url(url: str) -> Result[str, HttpError] {
    let response = await http.get(url)
    return response.text()
}
```

`async fn` returns a `Future[T]`. `await` suspends the current task until the future resolves.

### 8.2 Task Spawning

```tll
fn main() {
    let task1 = spawn fetch_url("https://example.com")
    let task2 = spawn fetch_url("https://other.com")

    let result1 = await task1
    let result2 = await task2
}
```

`spawn` creates a concurrent task. Tasks are scheduled by the TLL runtime (work-stealing scheduler).

### 8.3 Channels

```tll
fn main() {
    let (tx, rx) = Channel[int].new(100)  // buffered channel

    spawn fn() {
        for i in 0..10 {
            tx.send(i)
        }
    }

    for value in rx {
        io.println("received: {value}")
    }
}
```

### 8.4 Async Traits

```tll
interface AsyncDataSource {
    async fn read(self) -> Result[bytes, IoError]
    async fn write(self, data: bytes) -> Result<void, IoError>
}
```

## 9. Agent System (AI-Native Core)

The Agent system is what makes TLL **AI-Native**. Agents are not libraries — they are language-level constructs.

### 9.1 Agent Declaration

```tll
agent Researcher {
    // Agent identity
    name = "Researcher"
    description = "Searches the web and summarizes findings"

    // Tools the agent can use
    tools = [web_search, web_fetch, summarize]

    // System prompt (template)
    system = "You are a research assistant. Always cite sources."

    // Temperature, model, etc.
    config = {
        model = "default",
        temperature = 0.3,
        max_tokens = 2048,
    }
}
```

### 9.2 Tool Definition

Tools are functions that agents can call. They are declared with the `tool` keyword:

```tll
tool web_search(query: str) -> List[SearchResult] {
    description = "Search the web for the given query"
    // implementation: call search API
}

tool web_fetch(url: str) -> str {
    description = "Fetch the content of a web page"
    // implementation
}
```

Tools have automatic JSON Schema generation for LLM function calling.

### 9.3 Intent Declaration

Intents are high-level goals that can be dispatched to agents:

```tll
intent Research(query: str) -> Report {
    description = "Research a topic and produce a report"
    agent = Researcher
}
```

### 9.4 Using Agents

```tll
fn main() {
    // Create an agent instance
    let researcher = Researcher.new()

    // Send a message to the agent
    let response = await researcher.send("What is the TLL programming language?")
    io.println(response.text)

    // Use an intent (higher-level)
    let report = await Research("TLL language features")
    io.println(report.summary)
}
```

### 9.5 Agent Composition

Agents can call other agents:

```tll
agent Manager {
    name = "Manager"
    tools = [delegate_to_researcher, delegate_to_coder]
    system = "You coordinate a team of specialists."
}

fn delegate_to_researcher(task: str) -> str {
    let researcher = Researcher.new()
    return await researcher.send(task)
}
```

### 9.6 Agent Memory

```tll
agent Assistant {
    name = "Assistant"
    memory = Memory.short_term(max_items: 100)
    // or memory = Memory.persistent(path: "./agent-memory")
}
```

### 9.7 Streaming

```tll
fn main() {
    let agent = Assistant.new()
    let stream = agent.stream("Write a poem about code")
    for await chunk in stream {
        io.print(chunk)
    }
}
```

## 10. Application Framework

TLL includes a built-in application framework for building services, APIs, and full-stack apps.

### 10.1 Entity (Data Model)

```tll
entity User {
    id: int = primary_key(auto_increment)
    name: str
    email: str = unique
    password_hash: str
    created_at: datetime = default(now)
    updated_at: datetime = default(now, on_update: now)
}
```

Entities are database-agnostic. The compiler generates migrations, repositories, and type-safe query builders.

### 10.2 API (Endpoint Definition)

```tll
api UserApi {
    base_path = "/api/users"

    GET "/" -> List[User] {
        description = "List all users"
        handler = list_users
    }

    GET "/{id}" -> User {
        description = "Get user by ID"
        handler = get_user
    }

    POST "/" -> User {
        description = "Create a new user"
        body = CreateUserRequest
        handler = create_user
    }

    PUT "/{id}" -> User {
        description = "Update user"
        body = UpdateUserRequest
        handler = update_user
    }

    DELETE "/{id}" -> void {
        description = "Delete user"
        handler = delete_user
    }
}
```

### 10.3 Application (Service Container)

```tll
application MyApp {
    name = "My Application"
    version = "0.1.0"

    // Modules to load
    modules = [UserApi, ProductApi, AuthModule]

    // Middleware
    middleware = [Logger, Cors, AuthGuard]

    // Configuration
    config = {
        port = 8080,
        database = "postgres://localhost/mydb",
        env = "development",
    }
}

fn main() {
    MyApp.run()
}
```

| Module | Description |
|--------|-------------|

### 11.2 Example: IO

```tll
import io

fn main() {
    io.println("Hello, World!")
    let name = io.read_line("What is your name? ")
    io.println("Hello, {name}!")
}
```

### 11.3 Example: JSON

```tll
import json

struct User {
    name: str,
    age: int,
}

fn main() {
    let user = User { name: "Alice", age: 30 }
    let serialized = json.to_string(user)
    io.println(serialized)  // {"name":"Alice","age":30}

    let deserialized: User = json.from_string(serialized)
    io.println(deserialized.name)
}
```

## 12. Testing

### 12.1 Test Functions

```tll
import testing

fn test_addition() {
    testing.assert_eq(2 + 2, 4)
}

fn test_string_length() {
    let s = "hello"
    testing.assert_eq(s.len(), 5)
    testing.assert(s.contains("ell"))
}
```

Functions prefixed with `test_` are automatically discovered and run by `tll test`.

### 12.2 Test Attributes

```tll
fn test_async_feature() async {
    let result = await some_async_function()
    testing.assert(result.is_ok())
}

fn test_should_panic() {
    testing.should_panic(fn() {
        panic("expected")
    })
}
```

## 13. Compiler Pipeline

```
Source (.tll)
    │
    ▼
Lexer ──► Token Stream
    │
    ▼
Parser ──► AST
    │
    ▼
Name Resolution ──► Scoped AST
    │
    ▼
Type Checker ──► Typed AST
    │
    ▼
IR Generation ──► TLL IR (Three-Address Code)
    │
    ▼
Optimization ──► Optimized IR
    │
    ▼
Code Generation ──► TLL Bytecode
    │
    ▼
TLL Runtime (VM / JIT)
```

### 13.1 TLL Bytecode

The TLL Runtime executes a register-based bytecode. Key instructions:

```
LOAD    r1, <constant>     // load constant
ADD     r1, r2, r3         // r1 = r2 + r3
SUB     r1, r2, r3
MUL     r1, r2, r3
DIV     r1, r2, r3
CALL    r1, <func>, [args] // call function
RET     r1                  // return
JMP     <label>             // unconditional jump
JEQ     r1, r2, <label>    // jump if equal
JNE     r1, r2, <label>
ALLOC   r1, <type>         // allocate heap object
FREE    r1                  // deallocate (managed by ownership)
AGENT_SPAWN  r1, <agent>   // spawn agent
AGENT_SEND   r1, r2, r3    // send message to agent
AWAIT   r1, r2              // await future
```

## 14. Versioning and Compatibility

- TLL follows semantic versioning (SemVer).
- Specification 0.x is unstable: breaking changes may occur between minor versions.
- Specification 1.0 will be the first stable release.
- The Bootstrap Compiler (TypeScript) version tracks the specification version.

## Appendix A: Grammar Summary (EBNF)

```
program          = { declaration } ;
declaration      = fn_decl | struct_decl | enum_decl | interface_decl
                   | impl_decl | agent_decl | tool_decl | intent_decl
                   | entity_decl | api_decl | application_decl
                   | import_decl | const_decl | type_alias ;

fn_decl          = "fn" ident "(" [ params ] ")" [ "->" type ] block ;
params           = param { "," param } ;
param            = ident ":" type ;

struct_decl      = "pub"? "struct" ident "{" field_list "}" ;
field_list       = field { "," field } ;
field            = ident ":" type [ "=" expr ] ;

enum_decl        = "pub"? "enum" ident [ generics ] "{" variant_list "}" ;
variant          = ident ( "(" type_list ")" | "{" field_list "}" )? ;

type             = primitive | ident | "[" type ";" int "]" | "List[" type "]"
                   | "Map[" type "," type "]" | "(" type_list ")" | type "?"
                   | "&" type | "&mut" type | "fn" "(" type_list ")" "->" type ;

statement        = let_stmt | assign_stmt | if_stmt | while_stmt | for_stmt
                   | match_stmt | return_stmt | break_stmt | continue_stmt
                   | defer_stmt | expr_stmt ;

let_stmt         = "let" "mut"? ident [ ":" type ] "=" expr ;
assign_stmt      = expr assign_op expr ;
assign_op        = "=" | "+=" | "-=" | "*=" | "/=" | "%=" ;

expr             = literal | ident | expr binop expr | unop expr
                   | expr "(" args ")" | expr "." ident | expr "[" expr "]"
                   | "(" expr ")" | block | if_expr | match_expr
                   | lambda | await_expr | spawn_expr ;

binop            = "+" | "-" | "*" | "/" | "%" | "**" | "==" | "!=" | "<" | ">"
                   | "<=" | ">=" | "&&" | "||" | "|>" | ".." | "..=" ;
unop             = "-" | "!" | "&" | "&mut" ;

block            = "{" { statement } [ expr ] "}" ;
lambda           = "|" params "|" "->" type block | "fn" "(" params ")" "->" type block ;
```

## Appendix B: Reserved for Future Versions

The following features are planned but NOT in 0.1:

- Traits / Type classes (interfaces cover 0.1 needs)
- Macros (procedural and declarative)
- Reflection
- Unsafe blocks (raw pointer manipulation)
- Inline assembly
- SIMD intrinsics
- WebAssembly as a compilation target (0.1 targets TLL Bytecode only)
- Multiple return values (use tuples)
- Named arguments (use struct literals)
