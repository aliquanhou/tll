当前限制（已知技术债）⚠️

🔧 cg_bootstrap_align workaround
优先级: P0 · 计划: v1.1 立即修复
根因: Bootstrap 编译器（TypeScript）的函数索引分配存在 off-by-one bug。当函数定义顺序特定时，cg_compileStatement 的调用索引解析错误，导致 main 函数只编译出 1 条 HALT 指令。
当前方案: 在 cg_compileBlock 之前保留一个空函数 cg_bootstrap_align，通过偏移函数索引来掩盖 bug。
影响: 代码中存在无意义的空函数，技术债已文档化。
📦 export const 不支持
优先级: P0 · 计划: v1.1 添加
根因: Module Linker 目前只处理 export fn，不处理 export const 和 export let。
影响: T3.5 跨模块常量引用失败，VERSION/AUTHOR 等常量无法跨模块导入。
当前方案: 无 workaround，需在 Module Linker 中添加常量导出/导入支持。
🔄 循环依赖为警告模式
优先级: P1 · 计划: v1.1 升级为硬错误
根因: 当前 Module Linker 检测到循环依赖时只输出 Warning，继续编译。
影响: 可能导致运行时无限递归或未定义行为。
当前方案: 警告可帮助调试，但生产环境应升级为硬错误。
🏷️ 不支持重命名导入
优先级: P1 · 计划: v1.1 添加
根因: 语法解析器未实现 import x as y 语法。
影响: 两个模块导出同名函数时无法区分，只能第一个导入获胜。
当前方案: 无 workaround，需在 Parser 中添加重命名导入语法支持。

v1.1 路线图

P0 立即执行
🔧 修复 Bootstrap 函数索引
深入分析 TypeScript 编译器的函数注册/调用解析机制，定位 off-by-one 根因，修复后移除 cg_bootstrap_align workaround。
📦 添加 export const 支持
在 Module Linker 中添加常量导出/导入支持，包括 export const 和 export let，使 T3.5 跨模块常量引用通过。
P1 短期
🏷️ 重命名导入
在 Parser 中实现 import x as y 语法，支持同名函数的区分导入。
🔄 循环依赖硬错误
将循环依赖检测从警告模式升级为硬错误，编译时直接报错退出，防止运行时无限递归。
P2 中期
⚡ VM 性能优化
优化字节码虚拟机的指令执行效率，包括寄存器分配、函数调用栈管理和常量池访问。
📚 标准库扩展
扩展标准库功能，包括 crypto、collections、testing、datetime 等模块，提升开发体验。
❌ 错误信息增强
改进编译器和运行时的错误信息，提供更精确的位置信息、上下文提示和修复建议。
P3 长期
🖥️ TLL OS 框架
构建 TLL OS 应用框架，包括 Application 声明式定义、项目管理、部署系统，实现 tll create/dev/build/deploy 全流程。
🤖 AI Agent 运行时增强
增强 Agent/Tool/Workflow 运行时，支持多 Agent 协作、持久化记忆、工具自动发现和工作流可视化。
💳 商业场景接入
接入支付、API 网关、Web 服务等商业场景能力，支持电商、SaaS 等真实商业应用开发。

  • ✓
    L4: 编译器字节码在 TLL VM 中成功执行，无崩溃、无 OOM
  • ✓
    L5: 编译器成功编译自身，生成有效字节码
  • ✓
    两轮一致性: 函数数 / 常量数 / 指令数完全一致（127/127 匹配）
  • ✓
    回归测试: 全部现有测试通过（Lexer 8/8, Parser 10/10, TypeChecker 13/13, Codegen 10/10）
  • ✓
    模块测试: T3.1-T3.5 模块链接器测试全部通过或状态不变
